# Agentic Marketing: rules for Claude

Read this file at the start of every session. Follow it over any default habit.

## Purpose

This repository holds an agentic digital marketing system, organized by stage, from strategy through analytics. Each folder carries its own data and its own skill file. You can run the whole loop from start to finish, or work on one part at a time.

## Folder map

Numbers in folder names set the order. Fill in every bracket before first use. You may add folders and sub-folders as the system grows.

| Folder | What it holds | Status |
|---|---|---|
| `00_CMO` | Chief marketing officer (CMO) briefing, the orchestrator for the whole system | Derived |
| `01_Strategy` | Positioning and the current operating plan | Derived |
| `02_Customers` | Ideal customer profile (ICP), plus acquisition and retention economics | Derived |
| `03_Campaigns/00_Influencers` | Creator, partner, and earned distribution | Mixed |
| `03_Campaigns/01_Paid_Media` | Paid search and paid social, broken out by platform | Mixed |
| `03_Campaigns/02_SEO_GEO` | Search engine optimization (SEO) and generative engine optimization (GEO) | Mixed |
| `03_Campaigns/03_Owned_Media` | Email, blog, podcast, and community | Mixed |
| `04_Analytics` | Site, revenue, and cohort measurement | Mixed |
| `99_Outputs` | The only place new files may be created | Working area |

Numbers set the order at every level. Any folder ending in `_data` holds source files only, is read only, and is never committed.

"Source" means original material that you or a data provider produced. "Derived" means written from source material, usually by Claude. Derived files can be wrong, stale, or circular, and they never outrank source files.

## Data and skill files in each folder

Every folder carries exactly one of two files, and the folder name tells you which:

- A folder where work happens has a `SKILL.md` saying how that work is done.
- A folder ending in `_data` holds source files and has a `README.md` saying what belongs there. Nothing inside it is ever committed.

- Before doing any work in a folder, read that folder's skill file. If it is missing, say so and ask how to proceed.
- If a folder's skill file conflicts with this file, this file wins on where files go and what may be edited, and I make the final call. Tell me about the conflict.
- Treat data files in every folder as read only unless I say otherwise.
- Skill files are instructions, not scratch space. Do not edit them without asking first. No exceptions.
- When I ask for a full loop, work through the folders in numerical order, reading each folder's skill file and data as you reach it. When I name a folder or a stage, stay in that folder and its data, and tell me if the work needs anything from another one.

## Folder and file rules

- Do not create a new file anywhere except `99_Outputs` unless I ask you to, specifically, to keep things clean and organized.
- Do not create markdown summaries, notes, scratch files, or working files unless I ask and name the location. If you think one would help, say so and wait for approval.
- Do not edit existing files in place without my approval. Do not create copies, versions, or files with "v2" or "final" in the name unless I say so.
- Never edit, rename, move, or delete anything without my approval.
- Do not edit this file without asking first, even if you think a rule should change. Tell me what you would change and why.
- Name new files in `99_Outputs` like this: `YYYY-MM-DD_area_short-description.ext`. The area is the folder the work relates to, in lowercase: `cmo`, `strategy`, `customers`, `campaigns`, or `analytics`. If the work spans more than one, use the main one. If it fits none of them, ask. Use hyphens inside the description and keep it to a few plain words. Examples: `2026-09-28_customers_survey-summary.csv`, `2026-09-28_campaigns_paid-media-test-plan.xlsx`.
- If you are unsure where something belongs, ask before saving it. Do not pick a location and tell me afterward.

## Data rules

- If you are unsure what a dataset is, what one row represents, or what a column means, stop and ask. Do not guess.
- Files in the data folders are the source of truth. If a markdown file disagrees with the data, the data wins, and you tell me about the disagreement before doing anything else.
- Keep de-identified files de-identified. Do not copy rows, verbatim responses, or small-group breakdowns into any other file. Report aggregates only.
- Every number you report needs its unit, its denominator, and the file it came from. If you cannot say where a number came from, do not report it.
- State the sample size next to any percentage. Say plainly when a group is too small to support a claim.
- Datasets stay local. The `.gitignore` in this repository excludes every data folder by default. Do not commit source data, and do not work around the ignore rules without asking.
- Be prepared to pull additional datasets in through connectors or application programming interfaces (APIs) and save them into a working folder with my approval and direction.

## Working style

- Ask one question at a time, and only when you cannot proceed without the answer.
- Say when you do not know something. Say when you were wrong.
- Give the plain word instead of the jargon word. Spell out every acronym the first time it appears in any document you write.
- Do not use em dashes.
- Date and timestamp decisions so we can see when and where they were made in the system.
- When I update a skill file or set a new direction, confirm where it should go and ask for approval. This is a dynamic system, like a codebase.
- If a request would require creating files, editing source data, or working outside this repository, tell me what you would need to do and wait for my go-ahead.

## Before you finish any task

Tell me which files you read, which files you changed, and which files you created. If the answer to the last two is "none," say so.
